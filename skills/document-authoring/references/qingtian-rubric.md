# 合肥“青天大模型”技术标（施工组织设计）评标质检与总工级撰稿标准

> 适用依据：《合肥公共资源交易大模型开发建设与应用管理暂行办法》（合公信〔2025〕82号）“AI 类人评审 + 雷达监测”评分体系。

---

## 一、为什么普通大模型写的施组在“青天评标”下拿不到高分？

普通大模型生成的施组存在四大典型通病，会被青天大模型精准识别并重扣分：
1. **大段密集“散文墙”**：一节连续堆砌 400～700 字不分段、无结构化控制表，机器解析信息熵极低，专家审阅视觉疲劳。
2. **万能口号套话泛滥**：充斥“高度重视、精心组织、科学管理、统筹安排、全力以赴、确保万无一失”等换任何项目都能套用的无效文本，触发雷达雷同/模板化扣分。
3. **“按规范要求”糊弄技术参数**：在关键指标处写“压实度按规范、终压温度达标、低于规定值不得摊铺、按规范频次检测”，既无现行国行地标编号，又无精确数值阈值，直接丧失“合规性”与“可落地性”得分。
4. **工程量、工期与机械投入不闭合（不算账）**：前章抄了清单工程量，后章列了机械表和工期，但从未验算“日均施工强度与机械台班产能是否匹配”，甚至出现前后工期节点、管径单位（`m` 写成 `m³`）、管基包角反向等专业硬伤。

## 二、总工级反套话“三段式”撰稿铁律（`author` 必须严格执行）

每个主要技术分项小节（如 `3.X`、`4.X`、`5.X`、`6.X`）必须采用高信息密度的专业工程结构，**单段连续纯叙述文字严禁超过 280 字**：

1. **工况锚定与控制痛点（≤160 字精炼导语）**：
   - 开门见山绑定本项目真实桩号/区段、交口名称、土质类别、埋深、邻近敏感管线及 `00-facts.md` 精确清单工程量。
2. **定量工艺工序与产能匹配验算（结构化分条 `- **工序名**：...`）**：
   - 关键控制性工序必须写出**产能闭合算式**：`清单工程量 ÷ 计划有效作业天数 = 日均施工强度 ≤ 拟投入主力机械台数 × 单机台班定额产能`（与第 4 章进度节点及机械表完全一致）。
   - 工艺控制全部给出定量参数（仪器精度如 `2″级全站仪`、松铺厚度、碾压速度与遍数、摊铺/初压/终压温度 `℃`、养护天数 `≥7d` 等）。
3. **现行标准强条与量化验收控制表（GFM 管道表）**：
   - 用紧凑表格承载技术标准与实测实量闭环，列明：`检验项目 | 现行规范标准号 | 允许偏差/合格阈值 | 检测方法与频次 | 责任岗位`。
   - **严禁在任何表格或正文中写“按规范”、“达标”、“符合规定”等无数值糊弄词！**
   - 市政工程常用现行标准参考（须按项目实际选用）：`CJJ 1-2008`（城镇道路施工及验收）、`GB 50268-2008`（给水排水管道施工及验收）、`JTG/T 3610-2019`、`JTG F40-2004`（沥青路面施工技术规范）、`JGJ 46-2024`/`JGJ 46-2005`（施工现场临时用电）、`JGJ 59-2011`（建筑施工安全检查标准）、`GB 50720-2011`（建设工程施工现场消防安全）、`CJJ/T 82`（园林绿化）、`DB34/T 5040`（安徽省建筑安全生产标准化）、`建设部令第37号`、`建质〔2018〕162号`。

### 插图与题注唯一标准格式（防双重重复图题）
- 制图脚本（`render_charts.py`）中 `title` 仅写纯图名（如 `"排水管道施工工艺流程图"`），**不加** `"图 3-1"` 前缀（避免章节调整时图内文字与正文图号错位）。
- Markdown 正文插入图片统一采用**单行写法**：
  `![图 3-1 排水管道施工工艺流程图](assets/fig02_pipe.png)`
  Word 编译器会自动读取 `![...]` 内的文字在图片正下方生成居中黑体图题——**严禁在图片下方再手写第二行 `图 3-1 ...`**，否则会出现双行重复图题！
- 表格题注统一在表体正上方写纯文本 `表 3-1 某某控制一览表`（不加 `**` 星号包裹），后接空行与管道表。

## 三、青天评标质检员（`inspector`）五维百分制评审规程

`inspector` 子代理充当合肥公共资源交易“青天大模型”AI 类人评审专家，必须逐章通读全部 `drafts/*.md`，对照 `00-facts.md`、`01-requirements.md`、`02-plan.md` 及注入的 `.workspace/qingtian_radar.json`，按以下五维量表严苛打分（**综合得分 ≥ 90.0 分且 `blocking_defects` 为空方可放行**）：

| 评审维度 | 满分 | 考核核心与扣分细则 |
|---|---|---|
| **1. 完整性 (`completeness`)** | **30 分** | 招标文件评标办法细分评分项 100% 实质响应；危大工程专节、重难点专节、附录人员最低配置逐项闭环；目录 `# 第X章` → `## X.Y` → `### X.Y.Z` 连续无跳号；规划图表全部落盘引用。缺评分项每处扣 5~10 分，跳号每处扣 3 分。 |
| **2. 针对性 (`specificity`)** | **25 分** | 方案紧扣本项目道路红线、交口搭接、地下敏感管线、土方调配平衡及五专业真实清单量；严查万能套话口号与“换个项目名也能用”的空泛段落。套话或脱离项目实际的泛化节每处扣 2~5 分。 |
| **3. 合规性 (`compliance`)** | **20 分** | 现行国标/行标/安徽及合肥地标引用准确；补疑与变更公告最新口径（工期、业绩、报价/材料要求）100% 对齐；无工程常识错误（如包角颠倒、单位错误、虚构子系统）；无“按规范要求”模糊糊弄词；严守明标/暗标红线。每处专业错误或模糊词扣 2~6 分。 |
| **4. 可落地性 (`feasibility`)** | **15 分** | 关键分项具备**“清单量 ÷ 作业工期 = 日均强度 ≤ 机械台数 × 台班产能”**定量验算；文字工期、阶段划分表、横道图、机械与劳动力计划跨章数据 100% 咬合无矛盾；工序参数具体可操作。无产能验算扣 5~8 分，跨章数据打架每处扣 4 分。 |
| **5. 规范性 (`normativity`)** | **10 分** | 版面呈“痛点 → 定量分项条目 → 规范验收控制表”清晰层次，无 >330 字不分段散文墙；表题图题编号连续且无双重图题；工程术语统一规范（如全篇统一“混凝土”）。散文墙每处扣 1.5 分，图表编号错乱每处扣 1.5 分。 |

### `03-qingtian-review.md` 强制输出结构

`inspector` 落盘的 `03-qingtian-review.md` 必须包含：
1. **五维量化评分总表**（逐维列出满分、实得分、核心扣分依据）；
2. **一票否决与阻断性缺陷清单**（精确到 `drafts/0X-xxx.md` 小节/行号、问题原文、专业整改标准）；
3. **分章节提质增效重修处方**（明确指出哪几段散文墙需拆表、哪几处需补国标号与产能算式）；
4. **文末必须附带严格合法的 JSON 评分卡代码块**（供 `qingtian_inspect.py --mode certify` 机器解析签发准入证）：

```json
{
  "inspector": "hefei-qingtian-v1",
  "scores": {
    "completeness": 28.5,
    "specificity": 23.5,
    "compliance": 18.5,
    "feasibility": 14.0,
    "normativity": 9.0
  },
  "total_score": 93.5,
  "verdict": "PASS",
  "blocking_defects": [],
  "chapter_rework": []
}
```

> **铁律**：只要存在任何阻断项（如模糊词超标、严重散文墙、无产能验算、跨章数据矛盾、漏评分点），必须在 `blocking_defects` 中如实列出，并将 `verdict` 设为 `"REWORK"`，绝不允许放水虚报 90 分！
